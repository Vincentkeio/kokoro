# Agent 指令与测试安全边界

Hub 只下发结构化指令。Agent 不接受远程 `shell`、自定义可执行程序、脚本地址、工作目录、命令参数或测试超时。SWAP 调整只接收 MiB 数值，由 Agent 固定实现执行；systemd 安装使用独立的一次性服务，避免给常驻 Agent 增加 `CAP_SYS_ADMIN`。

## 测试指令

```json
{"id":"task_id","type":"test","payload":{"kind":"bench"}}
```

SWAP 管理指令只接受 `size_mb`，范围为 128–524288 MiB，表示节点 SWAP 总容量目标。SWAP 只支持增加，不支持减少；目标不能低于节点当前 SWAP 总容量。Agent 保留其它 SWAP 来源，并按总目标减去它们的容量后增加 Kokoro 管理的文件；目标等于当前容量时不做调整。

`kind` 只允许：

| 类型 | 内容 | Agent 超时上限 |
| --- | --- | --- |
| `bench` | 系统信息、CPU、内存及磁盘读写 | 30 分钟 |
| `ipquality` | IP 质量与服务解锁 | 15 分钟 |
| `netquality` | 网络测速与三网回程 | 20 分钟 |

具体流程和参数由 Agent 本地定义。现有测试工具按固定 Git 提交获取，并验证 Agent 编译时固定的 SHA-256。GitHub 不可达时可获取 Hub 副本，但仍须通过相同校验。Hub 不能通过修改下载副本改变 Agent 执行的代码。修改测试工具需更新 Agent。

工具写入权限受限的独立临时目录，测试结束后清理。CPU、内存与磁盘测试均由固定版本的测试脚本执行；缺少 sysbench、fio、python3 等组件时，脚本按需安装，软件包索引缺失时先更新再重试。锁等待和安装有超时上限，安装失败会报告原因。结果以 NDJSON 上报；某项失败会明确标记，已完成的其他项目仍可查看。

systemd Agent 保留 `ProtectSystem=strict`。缺少组件时，测试脚本调用本机固定的 `kokoro-test-dependencies.service`；该服务仅通过编译时固定地址和校验值取得测试脚本，并使用固定 `--prepare-only` 参数安装固定组件，无命令或组件参数入口。此服务按需启动，无常驻进程，也不接受 Hub 指令参数。安装器会创建它；已有安装可用安装脚本的 `--repair-service` 修复服务配置。

安装服务使用可遍历的 `/` 作为工作目录，测试脚本保留在独立权限受限的临时目录中。固定组件包含 CPU/内存的 sysbench、磁盘 fio、网络测速、Python JSON 解析，以及 IPQuality 所需的 curl、jq、bc、DNS、netcat 和 iproute 工具。

## 任务交付与结果确认

同一节点每次只持有一条运行中测试，后续测试留在 Hub 队列中。Agent 在执行前将任务写入本机配置目录旁的 `task-results/`，并随指标上报当前持有的任务编号。未确认收到的下发会用同一编号重试，Agent 按编号去重。

完成结果先保存在本机，再发送给 Hub。Hub 只有成功写入数据库才确认；网络或数据库失败时，Agent 每 10 秒重试已保存结果，不重复执行测试。重复回传不会重复写动态或覆盖已保存结果。

Agent 重启后会把尚未完成的本机任务报告为中断，不自动重新跑分。正常停止会取消测试并终止其子进程。Hub 根据任务确认和持有状态识别丢失任务，并以执行上限加两分钟回传宽限结束过期记录，避免无限显示测试中。

## 各省探测点

| 指令 | 允许参数 | 行为 |
| --- | --- | --- |
| `netq_targets` | `provinces`、`interval_min` | 更新内置省份选择与探测间隔，唤醒探测循环 |
| `netq_catalog` | `catalog` | 校验并更新探测点目录，使用 Agent 内置 ICMP/TCP 探测逻辑 |

省份须在内置列表内，间隔为 -1（关闭）、0（连续）或 1～1440 分钟。目录限制大小和数量；只接受三网及预定义境外运营商分类，地址须为有效公网 IPv4，不接受命令或脚本字段。

`reconfig` 仅允许上报间隔、节点名称和探测间隔；`restart` 无参数。`upgrade` 仍仅报告占位信息，`uninstall` 仍拒绝执行。未知类型和未知参数返回明确失败结果。

## 后台请求保护

Agent 白名单与后台跨站保护同时生效。后台仍拒绝不匹配、缺失或不透明的请求来源。页面采用 `strict-origin-when-cross-origin` 来源策略，避免正常同站表单因 `Origin: null` 被误拦。

## 网络、磁盘与依赖边界

Agent 的注册、指标与任务结果请求只允许同源重定向，不允许更换主机或端口、从 HTTPS 降级为 HTTP，防止注册令牌和请求体被带到其他站点。自签证书的指纹固定仍生效；用户明确配置的 HTTP Hub 仍可使用。

增加 SWAP 前校验磁盘空间，创建新文件后至少保留 512 MiB 可用空间；新文件从创建开始即为 0600。新文件使用 root 独占的 `/var/lib/kokoro-swap/`，避免与非 root Hub 的数据目录共用和互相修改目录权限。旧版 `/var/lib/kokoro/swapfile` 继续作为既有 SWAP 保留，新增文件只补足总目标差额，旧启动记录不会删除。该限制不改变目标容量及只允许增加的规则。升级后须使用安装脚本的 `--repair-service` 或 `--upgrade` 同步一次性服务路径。

固定测试脚本源码维护在 `scripts/kokoro-bench.sh`，发布时以不可变提交地址及编译期 SHA-256 固定。IPQuality 的执行脚本和 DNSBL 清单、NextTrace 下载成品也固定版本并校验 SHA-256。DNSBL 使用校验后的本地文件，避免远程清单内容被插入 shell 命令。现有系统组件可继续使用；缺失组件仍由固定安装服务通过系统软件源补齐。

这些限制不代表被入侵的 Hub 没有影响：它仍可滥用允许的测试、重启、配置和增加 SWAP 操作。Agent 拒绝任意命令及自动远程升级，但节点初次安装、人工更新仍依赖管理员选择可信安装来源；系统软件源和固定第三方工具也是信任边界。

## 升级

需同步升级 Hub 和全部 Agent。旧 Agent 不支持 `test` 指令；新 Agent 明确拒绝旧 `shell` 指令。旧排队任务只按存储的测试类型转换为新指令，不再下发历史 `Cmd` 文本。
