# 安全加固记录

日期：2026-10-14。适用版本：v0.1.1 Hub 与 Agent。此记录说明实际修复和验证范围，不代表系统不存在其他漏洞。

## 已修复的问题

| 边界 | 原问题与影响 | 修复 |
| --- | --- | --- |
| 主题布局 | 布局长度仅检查函数外形，可能在 calc/var 参数中插入 CSS 或 HTML | tokens、深色 tokens 与布局长度统一校验注入字符、控制字符和资源引用 |
| 主题资源 | URL 只要求整段字符串出现本地资源标记，可放过带该标记的外部域名或第二个外部 URL | 逐个校验每个 url；只允许规范本地路径或受限的图片 data URI，禁止其他资源函数和 SVG data URI |
| 主题包 | 重复清单或资源路径可产生不同读取结果；摘要受 ZIP 内部顺序影响 | 拒绝重复条目，按路径排序计算摘要，保留现有大小、文件数、解压比、符号链接与路径穿越限制 |
| 主题持久化 | 启动时删除全部导入主题，升级可能丢失自定义主题 | 按新规则重新校验并恢复合法主题，不安全存档跳过且保留原文，不再批量删除 |
| 主题抓取 | 自有域名自动允许任意回环端口；含密码的来源 URL 可公开展示 | 自有域名默认只允许 80/443 或明确配置的站点端口；拒绝 URL 内嵌用户名密码；保留显式旧白名单的管理员授权语义 |
| 公开实时流 | 私有与未列出节点的指标、状态和任务提示传给所有连接，再由浏览器决定是否显示 | 服务端按可见性过滤指标、状态、三网与任务卡；通知只发给有效管理员会话；未列出节点在其明确详情链接中仍能实时更新 |
| 实时流并发 | 断开客户端时关闭通道，可能与正在广播的发送并发，导致 Hub panic | 注销订阅时不关闭广播快照可能持有的通道，慢公开客户端不会阻塞其他客户端 |
| Agent 传输 | 默认 307/308 跳转可能把注册请求体带到其他主机；默认认证头也可能转发到子域名 | 只允许相同协议、主机及端口的跳转；禁止 HTTPS 降级，兼容默认端口等价写法和正常同站跳转 |
| 执行依赖 | 固定外层脚本仍执行浮动 IPQuality 或 NextTrace 安装器；DNSBL 文本会被插入 shell 命令 | 固定并校验 IPQuality 脚本与 DNSBL 文件、NextTrace 二进制；DNSBL 过滤为安全域名后仅使用本地副本；不执行浮动安装器 |
| SWAP | 大容量请求可能用满磁盘；新文件分配时权限不够严格；状态目录与非 root Hub 数据目录共用 | 保留至少 512 MiB 空闲；以 0600 独占创建；使用 root 独占 /var/lib/kokoro-swap；旧 SWAP 和旧 fstab 项保留，目标容量仍按全部 SWAP 总量计算 |
| 登录与上报 | 登录前无会话时未校验浏览器来源；损坏的空 PBKDF2 密钥可误判验证成功；硬件更新缺少初次注册的字段界限；取消任务 ID 可无限累计 | 校验浏览器登录来源，校验盐与密钥长度，硬件更新复用字段长度和类型界限，限制任务响应和取消状态数量及 ID 长度 |
| 探测点 | CGNAT 共享网段也被通用 IP 方法当作全局单播地址，可能探测云厂商内部地址 | 目录只接受公网 IPv4，额外排除 CGNAT、零网段和网络基准测试保留段 |
| 安装与维护 | 临时目录失败后使用可预测路径；维护脚本使用共享 /tmp 文件和关闭 SSH 主机密钥检查；更新脚本不兼容完整 checksum 文件 | 临时目录创建失败即停止，维护临时文件置于私有目录，SSH 记住并核对已知主机密钥，支持裸哈希和标准 checksum 文件 |
| Hub 服务权限 | 旧维护部署以 root 运行，且允许修改程序目录；升级材料在工作目录中校验后执行；旧 SWAP 与数据目录共用 | 维护服务改为 kokoro 用户，清空 capabilities；只允许写运行数据，分发目录在 Hub 服务中只读，旧 SWAP 文件对 Hub 不可见；升级文件在 root 私有目录校验，失败即停止，二进制目录由 root 持有 |

## 功能保持与验证

- Agent 继续执行固定 test、swap、reconfig、netq_targets、netq_catalog、restart 指令；拒绝自定义 shell、脚本 URL、可执行程序、参数和超时。远程 upgrade 不自动替换程序，uninstall 不执行删除。
- 合法颜色、字体栈、渐变、calc/clamp/var 和本地壁纸继续可用；六套内置主题通过解析、渲染及资源包测试。主题范例和规范已同步安全规则。
- 任务去重、本机结果记录、回传确认与重试、取消任务、增加 SWAP 的目标计算，以及公开/未列出/私有节点的实时边界均有回归测试。
- 新的 HTTP 重定向测试使用真实本机 HTTP 服务，确认注册请求体未送到第二个源，同源请求仍可完成。
- 测试脚本的完整性检查验证了正常文件、篡改文件和下载失败三种情况；固定 IPQuality 的本地 DNSBL 接口经过实际源文件转换和 Bash 语法检查。没有伪造外部检测结果。
- Go 1.27.2 构建 Linux amd64/arm64 成品；升级 golang.org/x/sys 到 v0.44.0；两个 Linux 架构的 govulncheck 未发现可达的已知漏洞。扫描依赖官方 Go 漏洞数据库，不覆盖未知漏洞或所有第三方脚本内部缺陷。
- 完整 Go 测试：378 项通过、18 项失败。修改前相同仓库的 Hub 基线有 27 项失败，本次没有新增失败；18 项均在原有失败清单中，涉及旧 UI、列表模式、主题切换和探测断言，不能把整套测试报告为全绿。合法浏览器表单测试已补上 Origin，回环测试显式授权本机临时端口，生产防护没有放宽。go vet、JavaScript、安装与维护脚本语法检查通过。

## 升级与信任边界

发布源代码与成品本身不会自动修改在线 VPS。要使修复生效，需要升级 Hub 和 Agent，并同步新 Agent 安装脚本及 systemd 服务；仅替换二进制不够。维护脚本会同步安装器并执行 `--repair-service`，保留节点令牌，不重新注册。旧 SWAP 按既有来源保留，新增加的差额写入新目录。具体部署和节点状态应在本地维护记录中管理，不放入公开文档。

被入侵的 Hub 仍能滥用已允许的测试、重启、配置与增加 SWAP 操作，白名单无法消除这些操作造成的资源消耗。它不能通过任务 payload 自由执行 shell 或修改编译时固定的测试代码。节点初次安装和人工更新依赖执行的安装器来源；如果管理员执行了受攻击 Hub 提供的恶意安装脚本，运行时白名单不能保护安装阶段。系统软件源、固定第三方工具、VPS 本机 root 和管理员开发机属于信任边界。明确配置的 HTTP 或 insecure 模式也会保留其原有传输风险。服务器部署地址、SSH 配置和线上节点信息不纳入公开审计记录。
