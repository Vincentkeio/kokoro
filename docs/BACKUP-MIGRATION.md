# 备份与迁移

入口：后台 → 系统 → 备份与迁移。

## 导出与恢复

1. 在旧面板设置至少 12 个字符的备份密码，点击“导出加密备份”，确认浏览器下载完成。
2. 在新 VPS 安装支持备份迁移的 Kokoro，并配置好域名和有效的 HTTPS。
3. 登录新面板，选择 `.kokoro` 文件、输入备份密码和“覆盖并恢复”。导入会覆盖新面板已有的数据。
4. 校验通过后面板会短暂关闭连接，在进程内重新启动。**用新面板当前的管理员账号登录**——导入的是数据，不是登录凭据；导入前后的浏览器会话都会失效，需要重新登录。

备份包括节点身份及认证记录、监控历史、文章、留言、站内消息、主题包、通知配置、头像、壁纸和上传图片。**备份不包含管理员账号和密码**：账密属于面板本身，不随备份迁移，导入后目标面板的账密保持不变（要改密码用 `kokoro passwd`）。数据库通过 SQLite 一致性快照导出，包含已提交但尚在 WAL 中的数据。备份使用 PBKDF2-SHA256 派生密钥和分块 AES-256-GCM 加密，必须提供原密码才能恢复。

由更早版本导出、里面带有账密的备份同样不会顶掉当前账密：导入时会保留目标面板现有的账密。

备份不包含程序、分发脚本、旧备份、SWAP、服务器服务配置或 TLS 私钥。图片外链仍然使用外链地址，不会下载为本地图片。数据总量上限 4 GB，建议至少预留约三倍数据量的空闲磁盘；导出和导入主要使用临时磁盘，避免将整个数据库装入内存。

密码错误、文件损坏、路径不合法、数据库校验失败或备份数据库版本过高时，不会替换现有数据。切换失败会回退；恢复前数据保存在目标服务器数据目录的 `backups/pre-import-*` 中，确认正常后可自行归档或清理。若进程在未提交的切换中退出，下次启动会根据恢复日志回退。

旧面板上尚未完成的测试任务不会在新面板重复执行。导出时间之后产生的数据不会自动合并到新面板。

## 同域名换 VPS

新面板导入完成后，将原域名的 DNS 指向新 VPS，探针会在解析更新后自动重连，无需重新注册。切换会有短暂离线，具体受 DNS 缓存影响。如果使用证书指纹固定，需要继续使用可匹配的证书链；面板备份不会导出系统证书私钥。

## 更换域名

1. 在新面板恢复**最近导出**的备份，并确保新域名 HTTPS 可用。
2. 回到旧面板，填写新面板完整地址，点击“验证并迁移探针”。
3. 旧面板先通过备份中的迁移身份验证新面板，然后向支持迁移的探针下发固定格式的地址切换指令。
4. 探针使用原令牌验证新面板、节点 ID 和备份身份，成功后保存新地址，在进程内重建连接。首次连接验证失败会恢复旧连接配置。新地址必须有系统信任的 HTTPS 证书。
5. 后台依据新面板收到的真实心跳显示“已到达”。请保留旧面板，直到所有节点完成迁移。

旧 Agent 不认识迁移指令，后台会显示“需要升级探针”；升级后继续使用原配置即可，无需重装或重新注册。离线节点会等待上线；测试任务执行中的节点会等待任务结束。失败节点按间隔重试，不会每次心跳重复切换。

“停止下发”只停止新的迁移通知，已经迁移或正在切换的探针不会自动回到旧面板。如果旧域名或旧面板已不可访问，更换域名后仍需手动修改尚未迁移的探针地址。
