# 后台程序更新

在后台 **系统 → 程序更新** 管理面板与探针更新。自动更新默认开启，可在此关闭，选择会保存并在重启后保留。

## 自动更新

每天北京时间（UTC+8）凌晨 **1:00** 检查本项目 GitHub 已发布版本，按发布时间判断是否有更新，兼容正式版与预发布版。首次启用后等待下一个 1:00；重启错过当日时间时也等待下一次计划，不在白天突然更新。检查失败后等次日 1:00 再检查。

1. 只给检查时在线且版本落后的探针下发更新。离线节点不加入计划，也不会在上线后补发本次任务。
2. 计划先保存到数据库。探针通过正常上报领取指令，每台每个计划只下发一次；下发记录也会保存，Hub 重启后不会重复下发。
3. 探针实际运行新版本并恢复上报后才算更新成功。失败后当天不自动重发；次日 1:00 检查时，仍在线且需要更新的探针可以再获得一次任务。整批任务最多等待 20 分钟。
4. 等探针任务完成、失败或超时后，才启动 Hub 自更新。等待中的 Hub 更新也会保存，意外重启后可继续处理。

关闭开关会停止后续自动检查并取消尚未启动的 Hub 自更新；已下发的探针任务和已启动的更新进程继续执行。需要立即重试时，可手动检查并发起更新。

## 手动更新

- **检查更新**：显示面板和在线探针是否有可用更新。复用已获取的发布信息，避免重复查询每个已安装版本；GitHub 限流时明确显示等待时间，并停止在限流恢复前继续请求。
- **更新面板**：下载官方发布文件，校验 SHA-256 和程序架构，再替换程序、重启并检查运行版本。探针更新进行中时需先等待任务结束。
- **更新全部探针**：仅处理当前在线且有可用更新的探针，保留配置、令牌、节点名称与历史数据。每台每个计划只下发一次，失败后可手动重试。

更新只下载所需架构的程序，不保留旧程序副本和数据库备份。刷新页面后仍可查看最近一次任务；检查时间按浏览器用户时区显示。

在线更新适用于 Linux + systemd，需要访问 GitHub。Hub 默认以非 root 身份运行，通过受限的 systemd 更新服务升级自身。过旧且不支持在线更新的探针需要先手动升级一次，界面会明确显示。

更新不会重新注册节点，也不会执行任意远程脚本。GitHub 尚未发布的提交不作为更新目标。

## 三网探测点列表

Hub 独立每 24 小时从上游同步一次目标 IP 列表，不绑定凌晨 1:00，也不受程序自动更新开关影响。首次运行时在后台同步；尝试时间会保存，重启不会反复拉取。

自动同步失败时保留原列表，不弹窗、不发通知、不创建失败任务，等待下一轮再试。同步成功后探针通过上报自动获取新目录；上游缺少 IPv6 时保留内置 IPv6 目标。后台手动刷新按钮继续可用。
